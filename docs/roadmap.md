## Дальше

Порядок — по влиянию на слышимую разницу с оригиналом; каждый пункт требует измерения и
подтверждения, «на глаз» поведение не меняем.

- [ ] **a.d.1 (effect type 0)** — ctl1 измерен точно, система `S` пока подогнанная модель.
      Открыто: память нелинейности не объясняется статической кривой; проверить гипотезу
      «петля с lowpass формирует и highpass» (первый фит застрял на −20.2 dB).
- [ ] **LP24 при resonance ≥ 120** — оригинал раньше входит в самоосцилляцию, осциллирует на
      1–2 % выше и сильнее подавляет входной шум (наши ~10 dB против ~21 dB).
- [ ] **Sync + FM** — хаотические ячейки при высоком FM; правило сброса фазы (`kSyncResetPhase`)
      подобрано частично. Судить по held-out сеткам + библиотеке, не по одной сетке.
- [ ] **Случайные последовательности** (arp random, S&H / smooth LFO) — структура известна,
      PRNG не идентифицирован. Кандидаты проверены и отпали (mac `rand()`, типовые LCG,
      окна noise-LFSR).
- [ ] **Хвост амп-огибающей** — закон между экспонентой и измеренными точками не найден
      (±2 % в середине decay); влияет на сильно перегруженные d.d.-патчи.
- [ ] **Portamento на 2+ октавы** приходит ~30 мс раньше; decay > 88 — на 0.5–1 % быстрее
      (release заканчивается на один 256-сэмпловый блок раньше).
- [ ] **Предел нот осциллятора выше 127** — похоже на предел Найквиста, а не на 127; нужно
      измерение поведения на высоких нотах / sample rate.
- [ ] **Денормальный остаток** после конца голоса (8960 сэмплов в оригинале) не моделируется —
      решить, слышимо ли это и стоит ли моделировать.

## Потом

- [ ] Худшие пресеты (`patch0106` +21 dB, `patch0025`, `patch0163` — sync + FM + arp + fx):
      разобрать после закрытия общих причин выше.
- [ ] Замер движка на реальном x86-ПК (`build_windows.bat --bench`): Rosetta на M4 не показывает
      ни код MSVC, ни кэши/порты ПК; текущие числа — ARM64 Windows (эмуляция x64).
- [ ] Порты Linux / другие форматы — только как PR, 1:1 с mac/Windows; официально не
      поддерживаются.
- [ ] Обновление doc-system при выходе новых версий (`init.py --upgrade`), шаблоны документов —
      если появятся.
- [?] **Открытые вопросы к пользователю:** нужен ли CI (GitHub Actions) и git-хуки; расширять ли
      обвязку за пределы Synth1 (сейчас — не-цель, см. [architecture.md](architecture.md)
      § Не-цели); нужны ли официальные сборки под Linux.

## Как обновлять

- Закрытый пункт: `[ ]` → `[x]`, запись в `CHANGELOG.md`, при изменении архитектуры — правка
  [architecture.md](architecture.md).
- Новый крупный пункт появляется вместе с задачей, а не задним числом.
- Отменённый пункт не удаляй молча: перенеси в [handoff](agents/handoff.md) с причиной или
  оформи [ADR](adr/README.md).
- После существенного пересмотра — `python3 scripts/doc_system.py touch docs/roadmap.md`.
