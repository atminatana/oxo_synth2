# Архитектура Oxo Synth2

Устройство кода и границы, которые нельзя ломать. Факты о звуке (измеренные законы Synth1) —
в [AGENTS.md](../AGENTS.md); где что лежит — в [project-map.md](project-map.md).

## Текущее состояние

Synth2 — воссоздание Synth1: те же 99 параметров (те же индексы), тот же звук, тот же звуковой
движок по поведению, но новый код, панель и обвязка. Один и тот же C++-движок используется
четырьмя оболочками; редактор на mac и iPad — один SwiftUI-код, на Windows — свой Win32/GDI+.

- **Движок**: header-only `oxo::s2` в `EngineCore/` (C++20, без платформенных заголовков).
- **Точки входа**: mac VST3 (`OxoSynth2VST3/`), AUv2 — обёртка SDK вокруг того же VST3,
  iPad AUv3 (`OxoSynth2AudioUnit/`), Windows VST3 (`Windows_Build/`).
- **Редактор**: `Shared/` (SwiftUI, общий для mac и iPad) и `Windows_Build/Source/` (Win32).
- **Внешние зависимости**: сабмодули `third_party/vst3sdk` (Steinberg VST3 SDK 3.8.1) и
  `third_party/AudioUnitSDK` (Apple, Apache 2.0); zlib для zip-банков; системные фреймворки
  Apple (SwiftUI, AppKit/UIKit, CoreFoundation). JUCE нет.

Поток данных одного инстанса:

```text
хост (DAW)
  │  параметры / MIDI / state / автоматизация
  ├── VST3 processor ───────────────┐
  ├── AUv2 wrapper → тот же VST3 ───┤
  ├── AUv3 Synth2Instance ──────────┤   сообщения / mailbox / атомарные флаги
  └── Windows processor ────────────┘
                                    ▼
                        SynthEditorCore (EditorCore/)
             патчи, банки, MIDI learn, program change, state, темы
                                    │  C-хуки OxoSynth2Bridge.h
                                    ▼
                    редактор: Shared/ (SwiftUI) или WindowsEditor (GDI+)
                                    │
                                    ▼
                 oxo::s2::Synth::Render — голоса → эффект → панорама →
                 EQ → delay → chorus → master volume
```

Редактор никогда не трогает DSP напрямую: он вызывает C-хуки и опрашивает состояние с частотой
30 Гц; правки параметров идут в хост (`beginEdit` / `performEdit` / `endEdit`), хост отдаёт их
процессору. AUv3 держит истину в `AUParameterTree` и применяет изменения на границе рендера.

## Целевая архитектура

Границы слоёв (снизу вверх, зависимость только вверх):

```text
EngineCore/     чистый C++20: параметры, .sy1, синтез, эффекты, библиотека, MIDI-сервисы.
                Зависит только от стандартной библиотеки и сгенерированных таблиц.
EditorCore/     переносимые сервисы редактора: состояние, файлы, настройки, темы, C-хуки.
                Зависит от EngineCore; платформенный код — под #if os(...) / _WIN32.
оболочки        OxoSynth2VST3, OxoSynth2AudioUnit, Windows_Build: SDK + EditorCore + UI.
UI              Shared/*.swift (mac + iPad) и Windows_Build/Source/WindowsEditor.cpp.
```

Правила зависимостей:

- `EngineCore/` не включает ничего платформенного, ничего из SDK и ничего из `EditorCore/`.
- `EditorCore/` может включать `EngineCore/`, но не Swift/SDK-типы в общих заголовках.
- `Shared/` обращается к движку только через `OxoSynth2Bridge.h`; `Shared/` обязан собираться
  под iOS (`#if os(macOS)` для mac-only кода).
- `OxoSynth2VST3/`, `OxoSynth2AudioUnit/`, `Windows_Build/` — единственные места, знающие свой
  хост-API; общая логика уходит в `EditorCore/`.
- `third_party/` не редактируется. Правки SDK — строковые патчи по сгенерированным копиям в
  `OxoSynth2VST3/CMakeLists.txt`, с `FATAL_ERROR`, если якорь патча исчез.
- Сгенерированные файлы (`MeasuredTables.hpp`, `LegacyTables.hpp`, `OxoSynth2Identity.h`) —
  только результат генераторов; руками не правятся.

## Инварианты

Каждый инвариант либо покрыт тестом, либо проверяется командой из [development.md](development.md).

1. **Идентификаторы параметров.** Индексы 0..98 = индекс строки `.sy1` = ID параметра
   оригинального AU. Менять порядок/смысл нельзя; значения — нативные целые (не нормализованные).
2. **Формат совместимости.** Тег состояния `'OXS2'`, расширение `.sy1` и UTI
   `com.oxo.music.synth1-patch` не меняются никогда: иначе ломаются сессии и патчи.
3. **Громкость — не патч.** Параметр 99 (master volume) живёт только в состоянии хоста: не
   пишется в `.sy1` и не сбрасывается загрузкой патча.
4. **Legacy-конверсия по точной версии.** Версии 100 / 105 / 106 / 107 / 108 конвертируются
   таблицами, прочие — без изменений; значения вне диапазона загружаются как есть и играются
   ближайшим допустимым. Зафиксировано `legacy_fixture.txt` и `check_legacy.py`.
5. **Идентичность — один файл.** Имена, bundle ID, коды AU, FUID VST3, папки и версия берутся из
   `Identity.xcconfig` (плюс локальный `Identity.local.xcconfig`); форк меняет только его.
6. **Чистая комната.** Оригинал изучается только по аудио и опубликованному AU-интерфейсу
   (`tools/s1ref`). Никакого дизассемблирования, декомпиляции и копирования графики.
7. **Паритет зеркал.** `EditorCore/Themes.hpp` повторяет `Shared/SynthTheme.swift`, а
   `EditorCore/UpdateCheck.hpp` — `Shared/SynthUpdateCheck.swift`; тесты парсят Swift-файлы, так
   что расхождение одной стороны падает.
8. **iOS-чистота `Shared/`.** Мак-код только под `#if os(macOS)`; проверяется typecheck-командой
   под iphonesimulator.
9. **Библиотека замкнута.** Патчи и банки живут только внутри библиотеки; ссылок на внешние
   папки нет, zip-банки не читаются на месте, фабричный банк read-only, ничего не пишется за
   пределы корня библиотеки.
10. **Реальное время.** В аудио-колбэке нет блокировок, аллокаций и файловых операций; обмен с
    редактором — почтовые ящики и атомарные флаги; фоновые потоки присоединяются при
    уничтожении, ни один поток не переживает плагин.
11. **Совместимость состояния.** Чанк `'OXS2'` читает старые версии (v1/v2 — громкость 64, без
    программы; v1..v3 — без темы); новая версия формата только добавляет поля.
12. **Сборка без IDE.** `make -C EngineCoreTests test` — полный шлюз для движка и переносимых
    сервисов; он должен быть зелёным до коммита.

## Не-цели

- Новые синтетические возможности, которых нет в Synth1: это воссоздание, а не «Synth3».
  Улучшения — только обвязка (MIDI Learn, темы, браузер, размер UI).
- Клонирование багов оригинала «на всякий случай»: сохраняются только те, что слышны в звуке
  (например, ring + detune + sub) и подтверждены измерением.
- Официальные сборки под Linux (порты приветствуются как PR, 1:1 с mac/Windows).
- VST2 / AAX / CLAP.
- Распространение сторонних банков патчей и любых файлов пресетов.
- Библиотека/импорт на стороне iPad-приложения: банками управляет плагин.

## Открытые вопросы

Это не «недоделки вообще», а места, где модель ещё не совпадает с оригиналом; подробности,
числа и испробованные гипотезы — в [AGENTS.md](../AGENTS.md) § Status and open items.

1. **a.d.1** — ctl1 измерен точно, система `S` — подогнанная модель; статическая кривая после
   линейных фильтров не объясняет память нелинейности.
2. **LP24 при resonance ≥ 120** — оригинал раньше входит в самоосцилляцию и сильнее подавляет
   входной шум.
3. **Случайные последовательности** (arp random, S&H / smooth LFO) — структура известна, PRNG
   нет; смена порядка выборок двигает счёт у патчей с ними.
4. **Sync + FM** — хаотические ячейки при высоком FM; правило сброса фазы подобрано частично.
5. **Хвост огибающей** — закон затухания между экспонентой и измеренными точками не найден.
6. **Portamento на 2+ октавы** и затухания > 88 — приходят на ~30 мс раньше / на 0.5–1 % быстрее.
7. **Предел нот осциллятора** выше 127 — похоже на предел Найквиста, а не на 127.
8. **Денормальный остаток** после конца голоса (8960 сэмплов в оригинале) не моделируется.

Решения по этим пунктам требуют измерения и подтверждения пользователем; менять поведение
«на глаз» нельзя.
